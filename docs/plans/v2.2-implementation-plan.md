# Harness Foundry v2.2 - 计划 (从 7.0 拉到 8.5)

> v2.1 已经把 code 域的战术栈 (codebase-memory + ripgrep + LSP) 集成完毕, 3 个核心 skill 落地, L1/L2/L3 测试覆盖, 文档齐全. 目标: 把 v2.1 推到 8.5/10.

## 评分瓶颈 (v2.1 当前)

1. **集成 / npm 包**: 无 npx 入口, bootstrap 步骤分散, Understand-Anything 路径硬编码 Linux.
2. **CI 严谨度**: verify.sh 5/6 步依赖 python3, CI 没真跑过.
3. **依赖声明**: codebase-memory 隐式依赖 Codex/Claude skill, README 没说清.
4. **i18n / 文档**: 英文 README 极简, 缺截图 / 视频.
5. **检索 / 索引**: skills/INDEX.md 不存在, 找不到最相关 skill.
6. **验证闭环**: 规则文档 x Skill 实际行为一致是黑盒, 没有 property test.

## Issue #WU-07: Property test: 规则文档 x Skill 行为一致性

**目标**: 自动验证 'Skill SKILL.md 描述的触发条件' 在 rule-router 中真实存在.

**不做**: 不做运行时行为测试 (那是 harness runtime 的事).

**验收**:
- 	ests/property/rule-skill-consistency.mjs 用 fast-check 或 proptest-js.
- 对每个 core skill: 读 frontmatter triggers -> 检查 core/orchestration/skill-preferences.md 是否在对应 agent_role/wu_type 路由中提到.
- 在 CI 中跑, 失败时报具体哪一个 skill 的哪一个 trigger 缺失路由.

**估时**: 6h (2h 选框架, 3h 实现, 1h CI 接入).

**依赖**: WU-04 (有 skills/INDEX.md 才能批量遍历).

**推荐分工**: code (TS 经验 + test-driven).

**实现提示**:
- 触发关键词集合来自 frontmatter.triggers + description 正则匹配.
- 不要求 100% 覆盖, 缺失路由只 WARN, 不 fail; 显式 deleted 才 fail.
